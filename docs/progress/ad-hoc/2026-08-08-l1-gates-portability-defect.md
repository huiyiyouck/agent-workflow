## 1. 一句话

`ci/gates/l1-gates.sh` 的取值函数按**字节**偏移跳过全角冒号，在 CI 的 GNU awk（**字符**语义）下取值被截断，导致 **G5 打回闸在 CI 上静默失效**、escA 用例红灯。

## 2. 症状与证据

- **CI 现状**：真源仓 `framework-checks` 自 **2026-07-27** 起持续失败，至今（2026-08-08）未绿。近 60 次 run 统计：失败 11 / 成功 12，**最后一次成功是 `2026-07-27T02:35:49Z`**。
- **失败点**：`sh ci/gates/run-fixtures.sh` → `❌ fixture 回归：bad-escA 未被拦下（应红）`。
- **本地/CI 不一致**：同一份 fixture 在 macOS 本地全绿、CI（Linux）红。
- **注意**：转红的那一批正是宣称修复该逃逸的 commit（`6dc4352` / `2f3fc3d`，游标 `c0dc32a` 写「U3.2 双逃逸修复收官、试运行放行条件满足」）。**该结论不成立**——修复只在 BSD awk 语义下成立。

## 3. 影响面（比红灯本身严重，必须理解后再动手）

`after_colon` 有 **4 个调用点**，其中 **3 个是 G5 打回闸的输入**：

| 行 | 变量 | 用途 |
|---|---|---|
| `:34` | `fv` | 关闭态判定（escA 加固）——**红灯来源，唯一显性症状** |
| `:92` | `ov` | G5 打回闸：Owner 验收取值 |
| `:97` | `final_val` | G5 打回闸：最终状态 |
| `:98` | `concl_val` | G5 打回闸：关闭结论 |

G5 在 Linux 上的实际行为（已实测）：

```
输入行： - Owner 验收（真源记录，未验收 / 打回则不得关闭）：打回（UI 不符）
剥括注后：- Owner 验收：打回（UI 不符）
  macOS  → 取值「打回（UI 不符）」→ case *打回* 命中 → 闸门触发   ✅
  Linux  → 取值「（UI 不符）」    → case *打回* 不命中 → 静默放行 ❌
```

**即：G5 打回闸——整个 L1 设计里防「免确认后最危险失效模式」的那道闸——在 CI 实际运行的平台上是 fail-open 的**：不报错、不亮红、就是不拦。这一点没有任何用例覆盖到，是靠 escA 的红灯顺藤摸出来的。

> 设计层面的讽刺：L1 全套信条是 fail-closed（门禁非绿一律不推进），但**门禁脚本自身在解析失败时 fail-open**。修复时请把这一点当作验收重点，不只是让 CI 变绿。

## 4. 根因（已精确定位）

`ci/gates/l1-gates.sh:16`：

```sh
after_colon() { awk '{i=index($0,"："); print (i? substr($0,i+3) : "")}'; }
```

`i+3` 的意图是「跳过全角冒号「：」的 3 个 UTF-8 字节」——**该写法默认 `index`/`substr` 是字节语义**。

| 平台 | awk 实现 | `index`/`substr` 语义 | `- 最终状态：已完成` 取值 |
|---|---|---|---|
| macOS（本地） | BSD awk | **字节** | `已完成` ✅ |
| Linux（CI） | GNU awk（UTF-8 locale） | **字符** | `成` ❌（多跳 2 字符） |

**同类隐患已全仓扫描：仅此一处。**（扫描口径：`substr(` / `index(` / `cut -c` / `cut -b` / `${var:n}`，覆盖 `l1-gates.sh` 与 `run-fixtures.sh`。脚本内其余 7 处 `awk` 用法均为按行/按字段匹配，不依赖字符偏移。）

## 5. 修复要求

**要求**：取值逻辑不得依赖 awk 的字符/字节语义，且**行为须与现行 macOS（字节语义）结果完全一致**——现行判据语义是正确的，坏的只是实现的可移植性。**不要借机调整任何门禁判据。**

**已验证候选**（纯 POSIX 参数展开，无 awk 依赖）：

```sh
after_colon() {
  while IFS= read -r l || [ -n "$l" ]; do
    case "$l" in
      *：*) printf '%s\n' "${l#*：}" ;;
      *)    printf '\n' ;;
    esac
  done
}
```

等价性实测（5/5 与现行 macOS 行为一致，含边界）：

| 输入 | 现行(macOS) | 候选 |
|---|---|---|
| `- 最终状态：已完成` | `已完成` | `已完成` |
| `- Owner 验收：打回（UI 不符）` | `打回（UI 不符）` | `打回（UI 不符）` |
| `- 关闭结论：可关闭` | `可关闭` | `可关闭` |
| `- 无冒号行` | *(空)* | *(空)* |
| `- 多个：冒号：的行` | `冒号：的行` | `冒号：的行` |

候选仅供参考，执行方可另拟等价实现；**等价性与验收标准不可打折**。

## 6. 验收标准（缺一不可）

1. **CI 绿**——`framework-checks` 在 **GitHub Actions（Linux）** 上通过。**本地绿不算数**：本缺陷的成因就是「只看本地」，也是历轮回执引 workboard 仓绿灯、从未核真源自身红灯所以拖了 12 天没被发现的原因。
2. **新增回归用例**：针对 G5 打回闸构造 fixture（`Owner 验收：打回` + `最终状态：已完成`），**必须在 Linux 上被拦下**。现有 fixture 集覆盖不到 G5 的取值路径，这是本缺陷潜伏的直接原因。
3. **防复发用例**：断言 `after_colon` 对含多字节字符的行取值正确，且该断言在 BSD 与 GNU 两种 awk 下结果一致（或验证实现根本不经 awk）。
4. **escA / escB 两个既有用例**在 Linux 上恢复按预期拦下。
5. `docs/regression-cases.md` 补一条对应条目（口径参照该文件既有写法）。

## 7. 边界与禁区

- ✅ 允许：改 `ci/gates/` 下的脚本与 fixture、`.github/workflows/`、`docs/regression-cases.md`。
- ❌ 禁止：改 `docs/baseline/` 任何文件、改任何门禁的**判据语义**（哪些算关闭态、哪些算打回、G1-G5 各自判什么）。本工单只修**实现的可移植性**。
- ❌ 禁止：为让 CI 变绿而放宽或删除 fixture。
- ⚠️ 注意：门禁脚本自身的变更属「改判卷人」类改动——**改完必须由独立会话复核**，不得自审自验。（这正是 BCR-014 防自审护栏要解决的问题；该护栏尚未落地，故本轮靠人工纪律。）
