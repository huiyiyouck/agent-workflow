## 一、总结论（先看这个）

**「固定链路 14433 超 P1 硬指标、fixture 26528 超 P2 硬验」是测量口径漂移导致的误报，不是真实膨胀。** 按 ROADMAP 历史基线同口径（UTF-8 字符数）复测，HEAD 实际为：

| 链路 | 误报值（字节口径） | 真实值（字符口径） | 硬指标 | 结论 |
|---|---|---|---|---|
| 固定规则链路 | 14433 | **7553** | <13000（P1 硬） | ✅ 达标，余量 42% |
| 真实启动链路 fixture | 26528 | **13538** | <15000（P2 硬验） | ✅ 达标，余量 1462 字符 |

P8→HEAD 的真实膨胀只有约 **+8%**（固定链 6992→7553，fixture 12473→13538），全部有对应 BCR 落地记录，属正常演进，**不构成瘦身动因**。「P10-P14 膨胀约一倍」的表象，一倍里约 92 个百分点是口径差、8 个百分点是真实增量。

## 二、误报机理（根因）

`measure-context.sh` 用 `wc -m` 计数。**`wc -m` 的行为依赖 locale**：

- `LC_CTYPE=UTF-8` 环境 → 按字符计数（ROADMAP 历史基线均此口径：P8 记录 6992/12473、P12 记录 7393/13378，本次均逐位复现）。
- `LC_CTYPE=C` 环境 → 退化为**按字节计数**，中文一字计 3——本仓中英混排实测比值约 1.9 倍。

本次触发误报的运行环境（Claude Code 沙箱 shell）locale 全为 `C`，故 14433/26528 实为字节数。验证：`printf` 同一份 `CLAUDE.md`，`LC_ALL=en_US.UTF-8 wc -m` = 2849，`LC_ALL=C wc -m` = 5569 = `wc -c`。

**波及面**：脚本注释「约 1.5-1.7 token/字」与两条硬指标阈值均锚定字符口径；CI（ubuntu runner，UTF-8 locale）跑出的是字符口径且仅展示不阻断——所以 CI 从未报警，报警只出现在 C locale 的本地会话，且一旦在这种会话里跑，**所有历史对比全部失真**。ROADMAP ⚠️ 条目把字节值（14433）与字符基线（6992）直接对比，是两种口径混算。

## 四、按 P1 方法论的定性

- **风险分级**：本问题不在规则内容层（无任何 P0/P1 规则膨胀失控），而在**度量基础设施层**。度量失真的风险是双向的：字节口径下会像本次一样误报超标、诱发不必要的压缩手术（压缩本身有砍伤 P0 红线的风险）；反之若阈值被误校准到字节口径，真超标时会漏报。定级 **P1**（门禁基础设施正确性）。
- **触发索引 / 压缩方案**：**不提出任何 baseline 正文压缩**。7553/13000 余量充足，按 P1 方法论「可达性优先于字数」，无超标则不动刀——压缩才需要动风险分级与触发索引，本次不需要。
- **回归用例**：应新增一条防复发用例（见 §五方案 A 第 3 点），保证脚本在任意 locale 下输出恒为字符口径。

## 五、订正方案（报 Owner 拍板）

**方案 A（荐）：脚本锁定字符口径 + 记录订正，零 baseline 正文改动**

1. `measure-context.sh` 开头锁定 locale（`C.UTF-8` 优先、`en_US.UTF-8` 兜底），并加自检：`printf '一' | wc -m` 不等于 1 时输出 WARN「当前环境退化为字节口径，数值不可与基线对比」。
2. ROADMAP 订正三处：⚠️ 存量问题条目改写为本审计结论（误报关闭）；「下一步」待办② 摘除；U1 段「measure 增量 0」订正为「固定链 +160 字符（7553/13000 内）」。
3. `docs/regression-cases.md` 新增用例：在 `LC_ALL=C` 环境运行 `measure-context.sh`，输出仍须为字符口径（或明确 WARN），防止口径再度静默漂移。

改动半径：`scripts/measure-context.sh` + `docs/ROADMAP.md` + `docs/regression-cases.md`，**不触碰 `docs/baseline/` 任何文件**——与 BCR-015 U3 将改写的停等条文（runtime/迭代速查的 S1-S4 区域）零交集，可在 U3 之前或并行落地。三个文件均为真源专属（不在 sync 分发集，见回归用例 I2 排除清单），**零回流**（初稿误写「经 sync 回流」，据分发集核实订正）。

**方案 B（不荐）：改按字节口径并重校准阈值**——需重写全部历史基线记录，且「token/字」估算锚定字符，字节口径与 token 相关性更差；仅作陪衬列出。

**给 U3 的预算提示（非本案范围）**：fixture 链路 13538/15000，余量 1462 字符。U3「S1-S4 拆句 + 上位条文 + 降级条款三件套」会向 runtime / 迭代速查加文字，此余量即 U3 的写入预算上限；建议 U3 方案里把「落地后 `LC_ALL=C.UTF-8 ./scripts/measure-context.sh` 复测 <15000」列为自检项。
