## 一、定位升级

### 1.1 结论

agent-workflow 从「Markdown SOP 真源」升级为「**SOP + Skills 双形态真源**」，实质是从"被阅读的规则文档库"升级为"**被执行 + 被测试 + 被监控的 AI 组织操作系统**"，三层结构：

| 层 | 承载什么 | 形态 | 特征 |
|---|---|---|---|
| **宪法层** | 组织法则、P0 红线、门禁、写权限矩阵 | baseline（保持不变） | 无条件常驻可达；改动走 BCR / 指挥官拍板 |
| **执行层** | 4 角色手册 + 4 机制（收尾 / 关闭检查 / 审计 / BCR 流转） | **标准 SKILL.md**（内容迁移） | 按需触发加载；带 evals 可回归；Gotchas 飞轮轻量迭代 |
| **工程层** | git hooks、校验器、sync 脚本、度量采集 | 脚本硬约束 | 不可绕过；错误输出写"给 AI 的指导" |

**分层判据（一句话）**：无条件必须遵守的进宪法层；被触发才需要的进执行层；能用脚本强制的下沉工程层。

### 1.2 为什么这个方向成立（三条论证）

1. **同构性**：agent-workflow 现有体系本质是"手工实现的 Skills 系统"——入口触发表 ≈ Skills L1 元数据路由、role-*.md ≈ L2 正文、templates/ ≈ L3 资源。P1-P3 手工做的瘦身 + 触发索引 + 按需读取，正是 Skills 渐进式披露的手工版。Skills 化不是范式转移，是把自制路由迁移到平台原生轨道，迁移成本天然低。
2. **标准化已完成（联网取证，颠覆交接说明的风险评估）**：Agent Skills 已由 Anthropic 于 2025-12-18 发布为开放标准（agentskills.io），被 40+ 工具采纳——OpenAI Codex、TRAE、Gemini CLI、Cursor、GitHub Copilot、JetBrains Junie、Kiro 等全在官方客户端名单。**SKILL.md 现在比自制 CLAUDE.md 路由更平台无关**；交接说明「Skills 化加深平台绑定」的风险陈述已过时，应订正。残留的唯一平台差异是各客户端 skills 发现目录不统一（`.claude/skills/` / `.trae/skills/` / Codex 自有目录）——这是 sync 脚本的工程问题，不是格式绑定问题。
3. **补齐工程闭环**：现有工作流有规划（PRD）、执行（角色）、约束（门禁），缺"反思"环节（运行数据回流成演进输入）与"强制"环节（P0 红线全靠模型自觉，如「禁止跳过 hooks」红线至今无 hook 存在，属空转）。四条升级主线本质是给框架补上单元测试（Skill evals）、强制执行（hooks）、生产监控（度量）、运行时资源管理（会话纪律）。

### 1.3 对参谋长职责的连带影响

参谋长从「文档维护者 + 回流执行者」扩展为「框架工程师」：新增维护 SKILL.md、evals、hooks 脚本、度量口径四类资产；职责④回流范围扩大（skills 目录 + hook 分发）。组织法则不变（参谋不决策）。

## 二、实现方案：六个升级方面

### ① 执行层 Skills 化（核心架构动作）

**架构决策（本方案的关键取舍，已按取证结果收敛）**：采用**迁移式**而非指针式——角色/机制内容直接迁入标准 SKILL.md，baseline 中对应文件退役；不支持 Skills 的平台由 runtime.md 路由表指向同一份 `skills/<name>/SKILL.md` 照读（SKILL.md 本身是 Markdown，纯文档降级路径天然存在）。**单一真源、标准格式、降级路径三者同保，不产生双轨漂移。**

- 曾考虑的备选「薄触发器指针式」（SKILL.md 只做触发器指向 baseline）：在「Skills 加深平台绑定」前提下才成立；该前提被取证推翻后，指针式只剩双文件维护成本，否决。

**试点顺序**：
1. **PM 角色 Skill 先行**（标准迭代唯一入口、高频、流程稳、交付物明确、有 Review 门禁兜底，"值得 Skill 化四标准"全中）。按官方"沉淀六步"执行：先拿 **3-5 个真实迭代 case 无 Skill 跑 baseline**，确认稳定暴露的失败模式 → 强模型复盘沉淀 SKILL.md → 换弱模型验收（检验 Skill 自足性）→ 按失败点补边界。
2. **收尾归档机制**作第二试点（最高频、纯 checklist、典型编排型）。
3. 其余角色/机制验证试点后再铺开；流程审计最低频，最后。

**约束**：
- 每个 Skill 都是上下文税：执行层 Skills 总量设上限（建议 ≤10，写入宪法层工具接入规范）。
- description 边界互斥：多个 Skill 触发范围重叠会让路由摇摆；现有入口文件「精准触发 / 模糊反问」表是现成的边界设计经验，迁移时复用。改 description 必须同步补正例 + 反例评测（官方实践要求）。
- 遵守官方规范硬约束：`name` ≤64 字符且与目录名一致、`description` ≤1024 字符、SKILL.md <500 行、L2 正文建议 <5k token；长资料进 references/、稳定动作进 scripts/。
- evals 结构：核心样本 5-10 + 边界 3-5 + 已知坑 3-5（evals.json：prompt / expected_output / assertions）。

### ② 工程层 Git 硬约束（确定性最高，建议最先落地）

- **commit trailer**：`Agent-Task`（挂现成 ID 体系：vX.Y / REQ-### / BCR-###）、`Agent-Decision`（关键决策及理由）、`Agent-Limitation`（已知局限）。注意：trailer 机制是 git 原生，但这三个键名是**生态内部约定**（业界无跨厂商标准，Co-authored-by 争议中，VS Code 2026-05 已回滚默认加注），不对外宣称标准。
- **commit-msg hook** 校验 trailer 完备性；落地后现有 P0 红线「禁止跳过 hooks」首次获得工程兜底。
- **收尾 / PR 模板补三节**：Key Design Decisions / Alternatives Considered / Known Limitations。
- **校验脚本两条纪律**：静默通过、只报失败；错误输出写成"给 AI 的指导"（错误信息是最好的 prompt 注入点）。
- **hook 分发**：`.git/hooks/` 不随现有 sync 分发，需扩 sync 脚本安装或用 `core.hooksPath` 指向仓内目录——**触碰下游 `.git/` 配置，超出现行"只同步框架文件"边界，需指挥官授权**（见第四节待拍板项 2）。

### ③ 轻量度量体系（补"反思"环节）

- 迭代关闭检查采集 4 指标：返工次数 / Review 缺陷数 / 门禁一次通过率 / 迭代历时。原始数据已在 R1/R2/R3 记录与阶段状态中，采集即"关闭时多填 4 个数字"，成本趋近零。
- 需先定口径（如"返工"的计数定义），随关闭检查模板改动一起落。
- 存放：项目内迭代记录采集，workboard 只读聚合（与现有"workboard 不回写"架构一致）；跨项目度量视图属 workboard 后续迭代，不在本次范围。
- 一人公司样本量小，指标短期无统计意义——定位是**趋势观察 + 反向驱动框架演进**（Harness「数据驱动进化」原则），不做考核。

### ④ 会话纪律与上下文治理（最便宜，随手落）

- context-policy 增补：80-100K token 主动开新会话（标注为**操作性经验值**，非研究常数；背后研究支撑为 Lost in the Middle 与 Context Rot，方向已证实）；「开新会话是正常流程而非失败重试」；以对话为单位组织任务的分段模板（调研→实现→测试→审查各开对话，靠结论引用 / git diff / 入口文件传递上下文）。
- 收尾检查加「列出观察到但未处理的问题」（发现即记录）。
- 入口 / 配置文件 ≤300 行审计（现状：multi-agent-workflow.md 恰 300 行卡线，其余均在线内；此条主要防未来膨胀）。
- 流程审计加「盘点长期未触发的 MCP / Skill 并移除」（30 天未用即候选）。

### ⑤ 工具接入规范（baseline 新章节）

- **分工判据（按 Anthropic 官方口径措辞，订正交接说明）**：不写「可选时优先 Skill」（此为社区引申），写「**互补分层：MCP 管连接，Skills 管程序性知识**」——精确参数验证 / 高频核心 / 跨项目标准化接口 → MCP（workboard 聚合后端、niuma-cheng-ai 对外能力）；复杂工作流 / 低频重要操作 / 多步组合 → Skills（角色与机制）。
- 进阶模式留一句：多步工具编排优先「Agent 写脚本 → 脚本调工具」（Anthropic Code Execution with MCP 推荐模式），压上下文。

### ⑥ 同步与回流管道升级（职责④资产扩容）

sync-downstream.sh 扩展四项：
1. skills 目录纳入同步范围（真源单一 skills 目录 → 按平台映射 / 链接到 `.claude/skills` / `.trae/skills` / Codex 目录）;
2. hook 分发机制（见②，需授权）;
3. `skills-ref validate`（官方校验器）做成同步硬关卡——与现有双入口逐字 diff 门禁同一模式;
4. 回流纪律不变：只准经脚本同步、禁止手改下游、每轮报备 + 回执 + 回填 BCR 池。

## 附录 B：官方 SKILL.md 规范要点（实施时的门禁依据）

- frontmatter 必填：`name`（≤64 字符，小写字母数字连字符，须与目录名一致）、`description`（≤1024 字符，写清"做什么 + 何时用"，含触发关键词）。
- 可选：`license`、`compatibility`（≤500 字符）、`metadata`（自由键值）、`allowed-tools`（实验性）。
- SKILL.md 建议 <500 行；L2 正文 <5k token；references/ 文件保持小而专，引用层级不超过一层。
- 官方校验器：`skills-ref validate <skill-dir>`（github.com/agentskills/agentskills 的 skills-ref 库）。
- 渐进式加载：L1 元数据（~100 token/skill，启动常驻）→ L2 正文（触发时）→ L3 scripts/references/assets（按需，脚本代码本身不进上下文）。

#### 三、方案漏掉的（调研里比 Skills 化更值钱的）

1. **强制 feature branch + git worktree 隔离并发 agent + Stacked PR**（08 篇）——对并行化最直接对症，全案最贵的遗漏。
2. **信号-噪音倒置 / 为 AI 定制测试脚本（只输出失败用例与关键错误）**（05 篇）——作用于每次开发会话，收益远高于把 `role-pm.md` 换个目录。
3. **Gotchas 飞轮应并入现有 corrections**，而非另起 evals 一套——`{role}-corrections.md`（≤30 条、强制首读、蒸馏结论）就是我们版本的 Compounding Engineering 且已在跑。**两套并行的经验沉淀机制是明确的坏味道。**
4. **Spec 模式（07 篇）与现有 PRD/design/迭代记录三件套已高度等价**——应写「已覆盖，不引入」，否则下次调研还会再提一遍。

#### 四、关注点答复（对应 §五）

1. **迁移式 vs 指针式** — 论证成立但**问错了问题**。该收敛的是「要不要迁」。降级路径在 Codex 下确实等价（SKILL.md 就是 Markdown）——这恰恰暴露：不支持的平台上 Skills 化**收益为零、维护成本照付**。
2. **≤10 上限** — 无需更细论证，现在是 0，属过早立法。
3. **度量 4 指标** — 见 M2，砍到可自动算的或整条转解析侧。
4. **hook 两种实现取舍** — 两条都别选，改 CI（少一次扩权 = 少一次边界腐蚀）。
5. **双入口门禁与 Skills 化协同** — 放进「实施设计范围」是**不成立的推迟**：它决定改动半径（白名单模型 + BCR-008 护栏 + 回归用例），属方案层必须回答的问题，**这一条本身就够格让方案回炉**。
6. **两处订正** — 「优先 Skill → 互补分层」**认可**（官方口径确为互补分层，"优先 Skill"是社区引申）；「平台绑定风险已过时」**不认可**（见 G3）。

#### 五、处置

指挥官 2026-07-25 决定**废弃**（原为搁置，后升级为废弃）。诊断的上游根因：

```text
错的顺序：读到好东西 → 推导框架该怎么改 → 发现与主线不同向（本案）
对的顺序：先定清楚目标定位 → 推导缺什么 → 才去看哪些调研能喂进来
```

后继方案已按正确顺序重做（见文首「后继方案」）。本案的**可用残值**已被后继方案吸收：G4（hook 拦不住自己 → 改走 CI）、M1 后半（模板补三节）、M3（会话纪律）、M2 建议（度量走解析侧）。
