**留（L1 明文不碰）**：口径以 `2026-07-25-fullchain-automation-bcr-draft.md` **§三之二「决策权分类」为唯一真源**（原「四项永久保留」表述与 BCR 梯度表口径冲突，已按「改变『什么算做好了』→ 永久保留；只决定『怎么把它做好』→ 分级下放」判据重切）。L1 保留 = **A 组全部 + B4-B9**：

- **A 组（永久保留）**：A1 目标设定与迭代立项 / A2 **重大变更的定性权与裁决权**（§11 原文「重大变更 = 产品范围·主流程·架构方案·部署方式·关键验收变化」即方向性变更）/ A3 验收否决权（打回，抽检是其行使方式）/ A4 对外不可逆动作放行（**含生产发布**，见下 S3 说明）。
- **B 组中 L1 仍保留**：B4 轻量变更确认 / B5 R3 死锁处置（不改范围前提下，改范围则升 A2）/ B6 角色调度与会话开闭（L2 的账）/ B7 核心产出 Review 方 <2 时的确认（质量底线）/ B8 跨项目承接（L3 的账）/ B9 迭代内优先级取舍与风险延期接受（**延期若使验收标准实质放宽 → 升 A2/A3**）。
- **存疑向上取整**：判不准属 A 还是 B 的，一律按 A 处理（升级 Owner）。这是 `multi-agent-workflow.md §11.2`「不能把重大变更伪装成轻量变更」的机制化。

**不碰（明确不在 L1）**：会话切换仍由人做（L2 编排层的事）——L1 砍的是每次会话里的"等确认"，不是"开会话"这个动作；Review 独立会话纪律不变；跨项目红线不变；Skills 维持搁置。

> 精确口径（R1 后重定义）：L0 人工介入 = 确认类 + 会话切换类；L1 只砍前者，切换类留给 L2，避免把 L2 的账算在 L1 头上。**晋级指标分子只计「本应被 L1 砍掉（S1-S4 范围）却仍发生的确认」**；A 组与 B 组保留项的确认（立项 / 打回 / 变更定性 / 延期接受等）**单独计数、不入分子**——它们是设计内行为，不是 L1 的失败。**阈值用相对指标：确认类介入较 L0 实测基线下降 ≥70%**（抗基线误差）；L0 基线与绝对阈值待阶段 0.2 实测后定（原 ~18-20 次系粗算，不作判据）。

## 二、三个建设块

### 块 1 · 验收可执行化（前提，其余都依赖它）

**改动核心**：PRD 验收标准从「可读」升级为「可执行」。

1. **PRD 模板**（`templates/prd.md`）：验收标准表新增两列——`验证方式`（脚本/测试/命令/人工抽检）与 `验证入口`（可执行命令或测试文件路径）。规则：
   - 每条验收标准**必须**填验证方式；能自动验证的填命令，确实无法自动验证的显式标 `人工抽检` 并写原因（不允许留空——「标不出验证方式的验收标准」本身就是 PRD 缺陷，Review 时按缺陷处理）。
   - 界面验收允许「构建通过 + 截图留档 + 人工抽检」组合，不强求端到端自动化（成本失衡）。
2. **Developer 自测**（`templates/test-report.md`）：自测报告新增「验收证据链」表——逐条验收标准 ↔ 验证入口 ↔ 执行结果 ↔ 证据链接。跑不过的不许标绿。
3. **实现阶段定稿条件收紧**（standard-iteration-quick / multi-agent §7）：原「Review 全过 + 自测证据齐备」→ 明确为「Review 全过 + **验收证据链全绿或标明人工抽检项**」。

### 块 2 · CI 机器门禁

**载体**：GitHub Actions（push / PR 触发），**L1 门禁工作流用约定名 `l1-gates.yml`**（区别于轻量/部署类 workflow，降级条款以它的绿灯结论为判据）。选 CI 而非 git hook（采纳 `2026-07-22-trae-skills-upgrade-design-deprecated.md` Review 记录 R1·G4 结论：hook 拦不住对自身的跳过，且 CI 不触碰下游 `.git/`，**零扩权**）。**首批只搭试点仓 workboard 的 CI**（四仓现均无 `.github/workflows`，CI 基建系从零搭建）；真源仓同期加轻量 workflow（跑 `measure-context.sh` + 双入口 diff）；其余两仓待各自进入试点时再搭。

**门禁项（首批 5 项，全部 fixture 化）**：

| 门禁 | 检查什么 | 实现 |
|---|---|---|
| G1 状态一致性 lint | 状态词命名空间不混用（已定稿/已完成/已归档）；vX.Y.md 阶段门禁表结构合法；INDEX 当前迭代状态与 vX.Y.md 一致 | 纯文本解析脚本（POSIX shell/awk，与现有脚本风格一致，零外部依赖） |
| G2 验收证据链核对 | 迭代进入关闭检查时：PRD 每条验收标准在自测报告证据链中有对应行，且状态为绿或「人工抽检」 | 同上 |
| G3 验收脚本执行 | 证据链中标为自动验证的条目，实际跑一遍其验证入口 | 项目自身测试命令。**试点仓 workboard 已有**（14 个测试文件 + `node --test`）；其余仓进入试点前先补（xiaobao 测试基建为 L1 范围外前置任务） |
| G4 Review 轮次完整性 | 定稿阶段的 Review 记录含轮次/结论/严重度；R3 未过而状态非「阻塞」时报错 | 纯文本解析 |
| G5 打回闸 | `Owner 验收状态` 为「打回」时，**禁止任何阶段状态前进**，直到出现新的验收结论——防免确认后最危险的失效模式：Owner 打回 → 下一会话未读到状态 → 门禁绿 → 静默重新放行 | 纯文本解析（状态词 `mechanisms` 已有，零新增字段） |

**输出纪律**：静默通过、只报失败；失败信息三段式「哪条规则 + 为什么错 + 该怎么改」（错误信息写给 AI 看，agent 读到即可自修）。

**上线前验证（分门禁定方式）**：G1/G4 所用字段在存量数据中已存在，对**存量历史迭代记录做静态回放**（人工核对报错全为真问题、误报清零后启用）；G2/G3 依赖 U1 才新增的「验收证据链」字段，存量数据无从回放，**走 fixture**（人造正负样本）；G5 走 fixture + 历史真实被打回迭代的回放（样本与晋级评审的注入式验证共用）。

## 三、实施与验证（对应整体走法 U1-U3）

- U1 = 块 1 + 块 3 模板部分；U2 = 块 2；U3 = 块 3 规则部分（U 批次定义见整体走法 §一元规则 1——交付批次，非标准迭代实例）。顺序不可换：先有可执行验收和留痕容器，再上门禁，最后才敢关停等。
- 每个 U 批次完成条件：回归用例全过（新增负向用例：门禁红灯不推进 / 验收标准无验证方式不定稿 / 打回后不静默重放行——对应 G5 打回闸）+ 双入口一致 + measure 复测不回归 + PR 合 main + 回流三下游。
- 试运行与晋级判据见整体走法 §二（确认类下降 ≥70% 相对指标 / 覆盖矩阵三项 / 注入式回放 + Owner 留痕回溯）。

## 四、风险

| 风险 | 应对 |
|---|---|
| 验收标准写不出验证方式，大量落「人工抽检」，L1 名存实亡 | 门禁 G2 统计人工抽检占比并写进迭代记录；否决线**分层**（试点仓 workboard 前端占比高，避免「L1 机制无效」与「项目天生难自动化」两件事互相污染数据）——**后端/解析层/数据层验收自动化率 100% 为硬指标**；界面层允许「构建 + 截图 + 人工抽检」组合，占比只记录不设否决线 |
| 免确认后坏产出流到终点才被发现，返工半径变大 | 每阶段门禁即时拦截 + R3 机制保留（连续不过仍升级 Owner）；打回案例强制转 corrections + 门禁补强候选 |
| CI 与半自动会话并存期的混乱（agent 不知道等不等人） | **免确认条文内置降级条款（结论探测，非能力探测）**：「约定名门禁工作流 **`l1-gates.yml` 在当前 commit 返回绿灯** → 阶段自动推进；**绿灯以外的任何状态**（红 / 未跑 / 进行中 / 查不到结论 / 无该 workflow）→ 维持 Owner 确认（旧行为），并按留痕义务第 5 条登记降级」。U3 合 main 后**三仓同时回流**（守职责④「改完顺手回流」，不产生多框架版本并行、无 `.workflow-version` 漂移）；行为切换由**门禁结论**决定而非仓的配置状态——首批仅 workboard 建有 `l1-gates.yml`，即天然试点。**判据取「绿灯」而非「有 CI」的原因**：真源仓轻量 workflow（measure + 双入口 diff）与 xiaobao 未来可能的 `deploy.yml` 都会造成「有 `.github/workflows` 但无 L1 门禁」的仓——能力探测会静默误授权，结论探测不会 |
| 界面/体验类验收难自动化 | 明文允许「构建 + 截图 + 人工抽检」组合，不为自动化牺牲验收真实性 |

## 五、给 review 方的关注点

> 下列 5 条为 R1 时提出的关注点，R1 已逐条答复（见 Review 记录）并按答复修订（其中第 2 条的「≤5」口径已废弃，现行口径见 §一精确口径段）；**R2 请重点核对 v2 修订处**：S1 拆句与上位条文改写面、G5 打回闸、A4 显式红线、晋级新口径、降级条款。

1. §一「砍/留/不碰」边界，尤其 S1-S4 四处停等的定性是否有误砍（正式清单以阶段 0.2 的 78 处台账为准，本表是其 L1 骨架）。
