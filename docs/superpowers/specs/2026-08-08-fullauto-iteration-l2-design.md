## 1. 目标形态（指挥官定义的规范化转译）

指挥官原始表述（2026-08-08）：确认 PRD（含界面要点）之后，架构详细设计 → 前后端开发 → 自测 → 部署上线全程自动；指挥官只做上线后的 UI 与功能验证，验证通过即收尾，迭代完成。第一版 PRD 由指挥官直接与 PM 确认；「多 PM 相互讨论确认」留待后续。

规范化为两个人工介入点：

| 介入点 | 时机 | 内容 | 对应决策权 |
|--------|------|------|-----------|
| ① 迭代起点 | PRD 阶段 | 指挥官与 PM 确认需求与界面要点，PRD 定稿 | A1（立项/目标）+ A2（范围定性） |
| ② 迭代终点 | 生产上线后 | 指挥官线上验证 UI 与功能；通过→自动收尾归档；打回→自动修复重发再验 | A3（验收否决权） |

两点之间（设计 → 实现 → 自测 → 部署 → 上线）**零指挥官停等**。

## 2. 与既定决策权框架（BCR-015 A 组）对照

| A 组 | 本方案处置 |
|------|-----------|
| A1 目标设定与迭代立项 | **保留** = 介入点① |
| A2 重大变更定性与裁决 | **保留**，转为中段升级路径：自动化过程中凡触及「改变什么算做好」（需求歧义无法自决、要改范围/放宽验收、架构方案推翻 PRD 前提）→ 停等回指挥官，不硬猜 |
| A3 验收否决权 | **保留** = 介入点②；打回沿用 G5 闸（打回期间禁止收尾与推进） |
| A4 对外不可逆动作放行 | **唯一需要修订的一项**，见 §3 |

结论：指挥官的定义与自己 2026-07-25 拍定的判据高度吻合，**宪法层只动 A4 的一个子项**。

## 3. A4 修订案（本方案唯一宪法级改动）

A4 现含四类：生产发布、删除受保护路径、force push、跨仓写入。修订**仅针对「生产发布」子项**，其余三类一字不动、永久停等。

**修订案：生产发布按「可逆性」切开——**

- **可自动发布**：纯代码变更（前后端代码、配置中可一键回滚项），前提三条全绿：`l1-gates` 门禁绿 + 部署就绪检查通过（含回滚预案验证）+ 本次变更不含下述任一不可逆项。
- **仍停等指挥官明示放行**：数据库 migration / 数据回填或删除 / 对外契约变更（coordination `contracts/`）/ 域名、证书、基础设施变更 / 首次上线（新项目第一次生产部署）。

理由：指挥官的验证点在上线后，生产环境成为第一验证现场——代码坏了可一键回滚（风险有界），数据和契约坏了回不去（风险非对称，维持 A4 原判据「失手代价无限」）。

## 4. 中段全自动 ≠ 裸跑（保留的机器侧结构)

1. **多角色独立互审保留**：设计/实现 Review 照旧，只是审的双方都是机器会话、不等指挥官；其可信性依赖 BCR-014 防自审护栏（产出方会话禁切 Review 角色）——故 BCR-014/016 为本方案**前置地基，同批落地**（方案已出：`docs/progress/ad-hoc/2026-08-08-bcr-014-016-guardrails-eval.md`）。
2. **门禁 fail-closed 照旧**：任何门禁非绿/查不到 → 不推进，退回指挥官 + 降级留痕。
3. **自动化中断条件（触发即停等，白名单式）**：a) 触及 A2（见 §2）；b) 触发 §3 不可逆清单；c) 门禁非绿；d) 外部依赖不可用/凭据缺失且无法降级；e) 单迭代资源预算超限（阈值默认「超 PRD 预估 3 倍」，可议）。
4. **留痕对偶照旧**：每砍一处停等，对应阶段执行记录加厚，指挥官可事后全程回溯。

## 5. 范围裁定：本次只建 L2，L3 挂起

指挥官定义的全自动完整落在**单项目单迭代**内 = 原梯度 L2（整迭代自动）+ A4 部分修订。L3（跨项目自动协调、多 PM 互审确认 PRD）当前无现实场景（存量项目全线暂停、新项目单体），**本次不建**——避免造空转机制；待新项目产生真实跨项目需求时另立 BCR。
